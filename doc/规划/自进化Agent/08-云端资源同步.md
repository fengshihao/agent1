# 08 — 云端资源同步（多类型 catalog）

> 2026-09-27：官方与策展资源放在**云端存储**；客户端**清单对比、增量拉取**；AI 知道「哪些需要更新」，避免每次全量下载。第一期用**简单清单 + 可信 CDN** 验证闭环。

**重要**：云端条目 **不限于 Skill**。同一套 manifest + Rsync 式 diff 可下发 **脚本、图片、原生库（.so/.dylib/.dll）、JS 三方库（如 three.js）、数据文件、模板包** 等；用统一 `kind` 区分，落盘到 `shared/catalog/` 下不同子目录。

## 目标

| 能力 | 说明 |
|------|------|
| **集中发布** | 多类型资源由云端维护版本（见下表 `kind`） |
| **增量同步** | 客户端对比远程清单与本机状态，**只下载新增或变更**条目 |
| **AI 可感知** | 模型知道当前目录版本、可用更新数量、可信源；不必用户手动 `wget` 全套 |
| **与本地进化共存** | 云端下发 ≠ 用户 `shared/` 晋升；加载时合并策略需明确（见下） |

同步语义对齐 **Rsync**（语音输入法曾误成 “I think”）：**只传与本机不同的部分**，基于校验/版本对比，避免每次全量重下。实现上可以分阶段：S1 用 **manifest + HTTP 拉取变更条目**（行为上 rsync-like）；后续可选用 **rsync 协议 / librsync 块级增量** 对大库包做真正的 delta 传输。

## 与本地 `shared/` 的分工

```text
┌─────────────────────┐     promote_request      ┌─────────────────────┐
│  Session workspace  │ ───────────────────────► │  shared/local/      │
│  (用户私有进化)       │                          │  (本机晋升产物)       │
└─────────────────────┘                          └──────────┬──────────┘
                                                            │ 合并加载
┌─────────────────────┐     sync apply (增量)              ▼
│  云端 CDN 对象存储   │ ───────────────────────► │  shared/catalog/    │
│  + 远程 manifest    │                          │  (同步下来的官方包)   │
└─────────────────────┘                          └─────────────────────┘
```

建议物理目录（在 [02-目录与权限模型.md](./02-目录与权限模型.md) 中扩展）：

```text
<agentRoot>/
├── sync/
│   ├── state.json              # 上次同步时间、各源 etag、错误计数
│   ├── remote/                 # 缓存的远程 manifest 副本（可选）
│   └── pending.json            # 可选：已发现未应用的更新列表
├── shared/
│   ├── catalog/                # 云端同步落盘（工具只读；写入仅 sync 模块）
│   │   ├── skills/             # kind: skill
│   │   ├── scripts/            # kind: script（QuickJS 等）
│   │   ├── assets/             # kind: image | font | media | data
│   │   ├── libs/               # kind: js_lib | qjs_module（three.js、lodash 等）
│   │   ├── native/             # kind: native（.so / .dylib / .dll，按平台分子目录）
│   │   └── bundles/            # kind: bundle（zip：混合包、Skill 树、多文件模板）
│   └── local/                  # Promotion API 写入的用户进化区（以 skill/script 为主）
│       ├── skills/
│       └── scripts/
```

**工作 Agent**：对 `shared/catalog/`、`shared/local/` 均 **只读**；改 catalog 只能 **`sync apply`**（或 CLI），改 local 只能 **Promotion API**。

## 远程清单（Manifest）— 第一期核心

不必自建复杂存储服务；**一个 HTTPS 上的 JSON 清单 + 静态对象 CDN** 即可验证。

### 资源类型 `kind`（manifest 统一描述）

| kind | 典型内容 | 落盘目录 | 运行时用法（示例） |
|------|----------|----------|-------------------|
| `skill` | SKILL.md 树 | `catalog/skills/` 或 zip→解压 | Skill 加载器 |
| `script` | `.js` 供 QuickJS | `catalog/scripts/` | `execute_script` file 路径 |
| `js_lib` | three.js、min 库单文件/UMD | `catalog/libs/js/` | 脚本 import / 注入路径 |
| `qjs_module` | QuickJS 可加载模块包 | `catalog/libs/qjs/` | Weizhi module 路径 |
| `image` | png/webp/svg | `catalog/assets/images/` | workspace 引用、UI、文档 |
| `media` | 音视频等 | `catalog/assets/media/` | 按需 |
| `data` | json/csv/小数据集 | `catalog/assets/data/` | 脚本只读读 |
| `native` | `.so` 等 | `catalog/native/<os>-<arch>/` | Weizhi native 插件目录（受平台约束） |
| `bundle` | 任意 zip（多类型混合） | 解压到 `catalog/bundles/<id>/` | 清单内 `manifest.yaml` 说明入口 |

条目 **必填**：`id`、`kind`、`version`、`digest`、`path`（相对 `baseUrl`）。  
**可选**：`platform`（如 `linux-x64`）、`mime`、`channel`、`dependsOn[]`（其他 catalog id）。

### 清单条目示例（`catalog-index.json`）

```json
{
  "schemaVersion": 1,
  "catalogId": "agent1-official",
  "releasedAt": "2026-09-27T00:00:00Z",
  "baseUrl": "https://cdn.example.com/agent1/catalog/v1/",
  "items": [
    {
      "id": "skill.weather-query",
      "kind": "skill",
      "version": "3",
      "digest": "sha256:abc…",
      "sizeBytes": 4096,
      "path": "bundles/skill-weather-query.zip"
    },
    {
      "id": "script.daily-standup",
      "kind": "script",
      "version": "1",
      "digest": "sha256:def…",
      "path": "scripts/daily-standup.js"
    },
    {
      "id": "lib.threejs-r160",
      "kind": "js_lib",
      "version": "160",
      "digest": "sha256:…",
      "path": "libs/js/three.min.js"
    },
    {
      "id": "asset.icon-set-v1",
      "kind": "image",
      "version": "1",
      "digest": "sha256:…",
      "path": "assets/images/icons.bundle.zip"
    },
    {
      "id": "native.weizhi-plugin-foo",
      "kind": "native",
      "version": "2",
      "platform": "linux-x64",
      "digest": "sha256:…",
      "path": "native/linux-x64/libfoo.so"
    }
  ]

```

**同步逻辑与 kind 无关**：一律按 `id` + `digest` diff；**加载/使用**由各运行时按 kind 注册（Skill 加载器、QuickJS lib 路径、native 插件扫描等）。

### 本机对比逻辑（Rsync 思想，S1 用清单实现）

与 `rsync` 相同的目标：**destination 已与 source 一致的部分不再传**。S1 不强制安装 rsync 二进制，用 **manifest 当 remote file list**，用 **digest 当校验和**：

1. 读取远程 `catalog-index.json`（If-None-Match / etag 可选）— 等价于先拿「源端列表」。
2. 读取本机 `sync/state.json` 或 `shared/catalog/**/.meta.json` — 等价于「目标端已有集合」。
3. **Diff**（rsync-like set difference）：
   - 远程有、本地无 → `to_fetch`
   - `digest` 或 `version` 不一致 → `to_update`
   - 远程无、本地有 → `orphan_local`（默认保留；是否 `--delete` 另策，对齐 rsync 可选删除）
4. **仅**对 diff 集合拉取；校验 `digest` 后落盘。大文件 P2+ 可对单对象走 **rsync/librsync** 减少字节数。
5. 写 `events.jsonl`：`catalog_sync_completed` + 变更 id 列表。

定时：CLI / cron / 启动时 `sync check`（**只对比清单**）；`sync apply` 才传文件（**只传 diff**）。

## 可信 CDN 与多源（第一期：文档 + 配置）

在 `docs/system/trusted-sources.md`（只读）中维护 **已验证源**：

| 字段 | 含义 |
|------|------|
| `sourceId` | 如 `official`、`mirror-cn` |
| `manifestUrl` | HTTPS 清单地址 |
| `publisher` | 签名方/维护方 |
| `status` | `verified` / `experimental` |
| `notes` | 稳定性说明 |

`agent.manifest.json` 或用户配置允许 **启用哪些 sourceId**；默认只开 `verified`。AI 通过 [07-系统提示词与环境摘要.md](./07-系统提示词与环境摘要.md) 得知：「官方清单 URL、当前仅信任 verified 源」。

**第一期甚至可以用现成 CDN**：例如 GitHub Release 资产 + `raw` 清单、Cloudflare R2 公共桶、对象存储静态网站——关键是 **HTTPS + digest 校验**，而非自研同步服务器。

## AI 如何「知道要更新哪些」— 不必全量下载

三层告知（由浅入深）：

1. **系统提示词摘要**（每 Run）：  
   `catalog: 127 items (12 skill, 40 script, 3 native, …), 3 updates pending` — 按 **kind 统计** + pending **id 列表**，不嵌入文件内容。
2. **工具 `catalog_sync_status`**（或 `sync check` 的 JSON 结果暴露给 Agent）：  
   返回 `{ upToDate, pending: [{id, kind, fromVersion, toVersion}] }`。
3. **按需 `sync apply --ids …` 或 `--kind script`**：  
   只拉 diff 集合；**禁止** Agent 直接写 `shared/catalog/`。

工作 Agent **可以**建议「更新 `lib.threejs-r160`」或「拉取图标包」；执行 sync 走 **CLI/专用工具**（类似 Promotion API，非 workspace write_file）。

## 「安装」= 与其他资源同一套（含 `.so`）

**下载 / 安装** 在 product 语义里 **不单独做一套 SO 安装器**。与 script、图片、js_lib 一样：

| 步骤 | 谁做 | 说明 |
|------|------|------|
| 发现需要某能力 | **AI 或用户** | 读文档：任务需要什么 `catalog` id |
| 对比是否已有 | **`sync check`** / `catalog_sync_status` | pending 里有没有该 `id` |
| **安装（落盘）** | **`sync apply --ids <id>`**（或专用 `catalog_install` 工具封装同逻辑） | 只拉该条目；native 仍走 HTTPS + digest，落到 `catalog/native/<platform>/…` |
| 使用 | **AI 按文档** | script/js_lib 用固定路径；native 用 `host.ensureNative("插件名")`（见 capabilities 与 Weizhi `AGENT_SNIPPET`） |

**AI 不能**：`write_file` 把 SO 拷进 catalog、不能 `apt install` 代替 catalog（除非文档明确写「系统级依赖」由用户/宿主处理，与 catalog 无关）。

**AI 应该**（按文档「按需安装」）：

1. 读 `docs/system/catalog-install.md`（出厂只读）：总流程、工具名、`--ids` / `--kind native` 示例。  
2. 读 `docs/capabilities/<id>.md` 或索引行：该资源 **when to install**、依赖 platform、装完如何验证。  
3. 若任务需要 `native.image_resize` 且 check 显示未安装 → 调用 **sync apply** 装该 id → 再按 snippet 写脚本。  
4. 若已安装且 digest 一致 → **跳过**，不重复下载（Rsync 思想）。

native 条目在 manifest 里通常是 **插件目录 bundle**（`manifest.json` + `lib*.so`，或 zip 解压），与「单个裸 .so 文件」可能等价，但 **sync 条目仍是一个 `id`**，和其他 kind 无差别。

**装完以后宿主可见**（实现细节）：`sync apply` 对 `kind: native` 成功后，除落盘外应 **刷新插件扫描路径**（或文档说明「新开 Session / 重启 CLI 后 ensureNative 可用」——实现时尽量自动，避免 AI 困惑）。

## 安全（第一期最小集）

- 仅 HTTPS；可选固定 manifest 公钥签名（P2）。
- 落盘前 **digest 必校验**；失败不写、记 audit。
- 不解压路径穿越（zip slip）检查。
- 云端脚本进 catalog 前与我们发布流水线绑定；**不等同**于用户晋升脚本。
- **native / .so**：仅允许来自 `verified` 源；落盘路径固定；加载前校验 digest 与 platform（Android/desktop 分 manifest 或条目级 `platform` 过滤）。
- 大图/大库：manifest 标 `sizeBytes`，Coach 可提示「需 sync apply，勿 read_file 整库进上下文」。

## 与加载链路的衔接

- **skill**：`shared/local/skills` 覆盖 `shared/catalog/skills` → 仓库 `.claude/skills`。
- **script / js_lib / qjs_module**：QuickJS 只读挂载 `catalog/scripts`、`catalog/libs/*`（路径写进 `docs/system/tools-and-quickjs.md`）。
- **image / data**：Session 脚本或工具通过 **workspace 相对引用** 或只读路径读 catalog（不复制进 workspace，除非用户/脚本显式 copy）。
- **native**：Weizhi `nativePluginDir` 指向 `catalog/native/<platform>` 子集（仅当前 OS/arch 条目）。
- **docs/capabilities/**：sync 成功后按 kind 分区更新索引（skills / scripts / libs / assets…）。

## 分期

| 期 | 范围 | 验证目标 |
|----|------|----------|
| **S1** | 单 manifest；**至少 2 种 kind**（如 `script` + `js_lib` 或 `image`）端到端；check/apply；pending 按 kind 统计 | 证明「非 Skill」同样走 diff |
| **S2** | 定时 check；`catalog_sync_status`；`docs/capabilities/*` 安装说明；可选 `catalog_install` 工具别名 | **AI 按文档按需 install**（含 native） |
| **S3** | 签名 manifest、channel（stable/beta）；大包 **rsync/librsync** delta | 规模化、省带宽 |
| **S4** | 用户私有云同步（跨设备 backup `shared/local`，可 rsync over SSH） | 与官方 catalog 分离 |

## 开放实现细节（记录备查）

- 包格式：单文件 vs zip（Skill、图标集、bundle 常用 zip + 解压）。
- 冲突：local 与 catalog 同名 id 是否警告（按 kind 分开命名空间：`skill.*` / `lib.*`）。
- three.js 等：**整文件同步**，脚本内用固定相对路径引用，避免 AI 每次从 CDN 临时下载。

### `kind: native` 与「类似 OpenCV 的重库」（通用模式）

不限 OpenCV：凡 **C/C++ 大库**（图像/音视频、推理引擎、加密、数据库引擎等）在 Agent 侧 **同一套路**：

1. **不**把上游整库 `.so` 丢给 QuickJS 随便 `dlopen`；  
2. 在 **Weizhi** 里为「Agent 需要的那几个能力」写 **IDL 薄插件**（`bytes` / `i32` 等），SO 内链或静链库的一小部分；  
3. 插件目录 `name/manifest.json + lib*.so` 经 **catalog sync** 落到 `shared/catalog/native/<platform>/`，宿主 **`enableNativePlugins`**；  
4. JS：`await host.ensureNative("name")` + 生成的 `AGENT_SNIPPET.md` 给 AI 用。

**方便之处**：接口窄、类型安全、可 CDN 按平台下发、可验签。  
**不方便之处**：每个库（或每个能力包）都要 **IDL + 编译 + 维护多平台 SO**，不是「npm 装一个就能用」。
- Android：catalog 同步在 App 内复用 core 模块，agentRoot 路径与桌面一致策略见 [05-开放问题.md](./05-开放问题.md)。
