# 08 — 云端资源同步（Skill / 脚本 / 库）

> 2026-09-27：官方与策展资源放在**云端存储**；客户端**清单对比、增量拉取**；AI 知道「哪些需要更新」，避免每次全量下载。第一期用**简单清单 + 可信 CDN** 验证闭环。

## 目标

| 能力 | 说明 |
|------|------|
| **集中发布** | Skill、脚本、库（含 QuickJS 模块包等）由我们在云端维护版本 |
| **增量同步** | 客户端对比远程清单与本机状态，**只下载新增或变更**条目 |
| **AI 可感知** | 模型知道当前目录版本、可用更新数量、可信源；不必用户手动 `wget` 全套 |
| **与本地进化共存** | 云端下发 ≠ 用户 `shared/` 晋升；加载时合并策略需明确（见下） |

口语里「类似 I think 的能力」在讨论稿中按 **「增量 / 按需更新（patch 思维）」** 理解：维护清单 diff，而非整包重下。若原意是其他产品名，可在 [05-开放问题.md](./05-开放问题.md) 更正。

## 与本地 `shared/` 的分工

```text
┌─────────────────────┐     promote_request      ┌─────────────────────┐
│  Session workspace  │ ───────────────────────► │  shared/local/      │
│  (用户私有进化)       │                          │  (本机晋升产物)       │
└─────────────────────┘                          └──────────┬──────────┘
                                                            │ 合并加载
┌─────────────────────┐     sync apply (增量)              ▼
│  云端 CDN 对象存储   │ ───────────────────────► │  shared/catalog/    │
│  + 远程 manifest    │                          │  (同步下来的官方包)   │
└─────────────────────┘                          └─────────────────────┘
```

建议物理目录（在 [02-目录与权限模型.md](./02-目录与权限模型.md) 中扩展）：

```text
<agentRoot>/
├── sync/
│   ├── state.json              # 上次同步时间、各源 etag、错误计数
│   ├── remote/                 # 缓存的远程 manifest 副本（可选）
│   └── pending.json            # 可选：已发现未应用的更新列表
├── shared/
│   ├── catalog/                # 云端同步落盘（工具只读；写入仅 sync 模块）
│   │   ├── skills/
│   │   ├── scripts/
│   │   └── libs/               # QuickJS/原生库等，按包 metadata
│   └── local/                  # Promotion API 写入的用户进化区
│       ├── skills/
│       └── scripts/
```

**工作 Agent**：对 `shared/catalog/`、`shared/local/` 均 **只读**；改 catalog 只能 **`sync apply`**（或 CLI），改 local 只能 **Promotion API**。

## 远程清单（Manifest）— 第一期核心

不必自建复杂存储服务；**一个 HTTPS 上的 JSON 清单 + 静态对象 CDN** 即可验证。

### 清单条目示例（`catalog-index.json`）

```json
{
  "schemaVersion": 1,
  "catalogId": "agent1-official",
  "releasedAt": "2026-09-27T00:00:00Z",
  "baseUrl": "https://cdn.example.com/agent1/catalog/v1/",
  "items": [
    {
      "id": "skill.weather-query",
      "kind": "skill",
      "version": "3",
      "digest": "sha256:abc…",
      "sizeBytes": 4096,
      "path": "skills/weather-query.bundle.zip",
      "channel": "stable"
    },
    {
      "id": "script.daily-standup",
      "kind": "script",
      "version": "1",
      "digest": "sha256:def…",
      "path": "scripts/daily-standup.js"
    }
  ]
}
```

### 本机对比逻辑（简单、确定性强）

1. 读取远程 `catalog-index.json`（If-None-Match / etag 可选）。
2. 读取本机 `sync/state.json` 中每个 `id` 的 `{version, digest}`（或扫描 `shared/catalog/` 侧车 `.meta.json`）。
3. **Diff**：
   - 远程有、本地无 → `to_fetch`
   - `digest` 或 `version` 不一致 → `to_update`
   - 远程无、本地有 → `orphan_local`（默认保留，仅日志；是否删除另策）
4. **仅**对 `to_fetch` / `to_update` 拉取对象；校验 `digest` 后解压/落盘到 `shared/catalog/`。
5. 写 `events.jsonl`：`catalog_sync_completed` + 变更 id 列表。

定时：CLI 后台 / 系统 cron / 启动时 `sync check`（**check 只拉清单，apply 才下包**）。

## 可信 CDN 与多源（第一期：文档 + 配置）

在 `docs/system/trusted-sources.md`（只读）中维护 **已验证源**：

| 字段 | 含义 |
|------|------|
| `sourceId` | 如 `official`、`mirror-cn` |
| `manifestUrl` | HTTPS 清单地址 |
| `publisher` | 签名方/维护方 |
| `status` | `verified` / `experimental` |
| `notes` | 稳定性说明 |

`agent.manifest.json` 或用户配置允许 **启用哪些 sourceId**；默认只开 `verified`。AI 通过 [07-系统提示词与环境摘要.md](./07-系统提示词与环境摘要.md) 得知：「官方清单 URL、当前仅信任 verified 源」。

**第一期甚至可以用现成 CDN**：例如 GitHub Release 资产 + `raw` 清单、Cloudflare R2 公共桶、对象存储静态网站——关键是 **HTTPS + digest 校验**，而非自研同步服务器。

## AI 如何「知道要更新哪些」— 不必全量下载

三层告知（由浅入深）：

1. **系统提示词摘要**（每 Run）：  
   `catalog: 127 installed, 3 updates available (skill.weather-query, …)` — 仅统计与 id 列表，**不嵌入包内容**。
2. **工具 `catalog_sync_status`**（或 `sync check` 的 JSON 结果暴露给 Agent）：  
   返回 `{ upToDate, pending: [{id, kind, fromVersion, toVersion}] }`。
3. **按需 `sync apply --ids …`**：  
   Agent 或用户确认后只拉指定 id；**禁止** Agent 直接写 `shared/catalog/` 文件。

工作 Agent **可以**建议「需要运行 sync apply 更新 skill X」；执行 sync 走 **CLI/专用工具**（类似 Promotion API，非 workspace write_file）。

## 安全（第一期最小集）

- 仅 HTTPS；可选固定 manifest 公钥签名（P2）。
- 落盘前 **digest 必校验**；失败不写、记 audit。
- 不解压路径穿越（zip slip）检查。
- 云端脚本进 catalog 前与我们发布流水线绑定；**不等同**于用户晋升脚本。

## 与加载链路的衔接

- Skill 加载器扫描顺序（待决，建议）：`shared/local/skills` 覆盖同名 `shared/catalog/skills` → 再仓库 `.claude/skills`。
- QuickJS `libs/`：同步到 `shared/catalog/libs/`，引擎 module 路径只读挂载。
- `docs/capabilities/`：sync 成功后由 **sync 模块**（非工作 Agent）增量更新索引行。

## 分期

| 期 | 范围 | 验证目标 |
|----|------|----------|
| **S1** | 单 `manifestUrl` + `sync check` / `sync apply` CLI；落盘 `shared/catalog/`；提示词显示 pending 数量 | 增量 diff + CDN 拉取稳定 |
| **S2** | 定时 check；`catalog_sync_status` 工具；trusted-sources 多源 | AI 主动提示更新 |
| **S3** | 签名 manifest、channel（stable/beta）、差分包 | 规模化与防篡改 |
| **S4** | 用户私有云同步（跨设备 backup `shared/local`） | 与官方 catalog 分离 |
