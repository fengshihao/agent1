# 06 — 环境文档（只读）与区外写入 API

> 2026-09-27 讨论结论：工作 Agent **可读**我们写好的环境说明，**不可改**；可写范围仅限 Session **私有目录**；私有目录外一律走 **晋升/发布 API**（初版自动同意 + **事后审计**）。

## 环境文档是干什么的

用户机器上的模型**不一定知道** Agent 的数据目录长什么样、各目录用途、工具边界。因此我们在安装/首次启动时，在 `agentRoot` 下放置**由我们编写、随版本发布**的说明文档（可与仓库 `doc/` 中「运行时说明」同步打包）。

工作 Agent 应通过 **`read_file`（及只读扩展根）** 主动阅读，例如：

- `agentRoot/docs/system/README.md` — 总览
- `agentRoot/docs/system/directories.md` — 各目录用途、可读/可写规则
- `agentRoot/docs/system/tools-and-quickjs.md` — 工具列表、QuickJS / `execute_script` 约定

**工作 Agent 不能用 `write_file` / `edit_file` 等 workspace 工具修改上述 `docs/system/**`。**

目的：让 Agent **理解环境**（自省），而不是让工作循环去「随手改手册」。

## 私有目录 vs 外部

| 区域 | 典型路径 | 工作 Agent 直接工具 |
|------|----------|---------------------|
| **Session 私有目录** | `sessions/<id>/workspace/**` | 可读可写（现有沙箱） |
| **外部（区外）** | `shared/**`、其他 Session、`docs/system/**`、`agent.manifest.json`、全局 `logs/` 等 | **不可写**；仅只读（若开放读根） |

口语里的「三审目录」按 **「私有目录」** 理解，即 Session 工作区。

## 区外变更：不走 Read/Write，走 API

约束（产品规则）：

1. 工作 Agent **不得**用现有文件工具直接修改私有目录之外的文件（即使 OS 权限允许，工具层也要拒绝）。
2. 需要把 Skill、脚本、摘要等沉淀到 `shared/` 或更新**非 system** 的索引文档时，调用 **`promote` / `publish` 类 API**（单独工具名待定）。
3. API 内部再交给 **审查侧**（可以是另一路 LLM 调用 / 独立服务）；**初版策略**：
   - **不拦截用户**：审查侧默认 **直接同意**；
   - **事后审计**：所有请求与落盘结果写入 `events.jsonl`（及可选 `logs/promotions.jsonl`），便于追溯与后续加严。

```text
工作 Agent（Session 内）
    │  promote_request(staging 路径、目标 shared/skills/…)
    ▼
Promotion API（CLI 内模块或本地 HTTP，首版同进程即可）
    │  规则扫描（体积、路径、密钥 pattern）
    ▼
审查 Agent / 审查 API  ← 初版：总是 approve
    ▼
执行落盘（唯一有权写 shared/、docs/capabilities/ 的代码路径）
    ▼
audit 事件追加
```

后续若要加强，只需把审查侧改为「可拒绝」或「需用户 y/n」，**工作 Agent 工具面不变**。

## QuickJS（口误纠正）

此前「GitGS」为 **QuickJS** 口误。脚本执行与自进化相关约定：

- Session 私有目录内：可用 **QuickJS**（及现有 `execute_script` / Weizhi 环）试验脚本；
- 晋升到 `shared/scripts/` 的条目在 metadata 中标注运行时（如 `quickjs`）；
- QuickJS 脚本**不能**作为绕过沙箱写区外的手段（引擎不暴露任意文件写 API，或仅暴露沙箱根）。

## 与 `docs/` 子目录的分工（修订）

| 路径 | 谁写 | 工作 Agent |
|------|------|------------|
| `docs/system/**` | 产品/安装包 | **只读** |
| `docs/capabilities/**` | Promotion API 落盘后更新 | **只读**（通过 read_file） |
| `sessions/.../workspace/**` | 工作 Agent | **读写** |

「能力增多后文档跟着变」= **晋升 API 成功后在 `docs/capabilities/` 增量更新**，不是工作 Agent 直接 edit 文档树。
