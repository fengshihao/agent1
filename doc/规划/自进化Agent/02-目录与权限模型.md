# 02 — 目录与权限模型

## 根：`agentRoot`

与现有生产力路径一致，由 `AGENT1_AGENT_ROOT` 指定；未设置时 CLI 当前默认项目下 `.agent1`，事件路径工具类默认 `~/files/agent`（**两处默认需在实现阶段统一**，见 [04-与现状对照.md](./04-与现状对照.md)）。

建议的**目标布局**（自进化完整形态）：

```text
<agentRoot>/
├── agent.manifest.json      # 自省入口：版本、能力清单、路径说明、组件列表
├── logs/
│   └── events.jsonl         # 全局事件（已有）
├── docs/                    # 「活文档」：能力索引、架构自述、MCP 说明（Agent 可维护）
│   ├── README.md
│   ├── capabilities/        # 按能力拆页：skill 索引、脚本索引、MCP 索引
│   └── journal/             # 可选：按日期/版本的变更摘要
├── shared/                  # 公共区：Session 可读；写入仅「晋升」通道
│   ├── skills/              # Claude 兼容 SKILL.md 树
│   ├── scripts/             # 可 execute 的脚本 + metadata.json
│   ├── templates/           # 文档/代码/配置模板
│   └── mcp/                 # MCP 服务器描述、允许列表、本地配置模板（非密钥）
└── sessions/
    └── <sessionId>/
        ├── meta.json
        ├── transcript.jsonl
        ├── runs/
        │   └── <runId>.json
        ├── workspace/         # Session 沙箱根（工具 RW 边界）
        │   ├── artifacts/     # 已有
        │   ├── .spill/        # 已有
        │   ├── notes/         # 可选：本 Session 私有笔记
        │   └── staging/       # 可选：待晋升草稿（skill/script 提案）
        └── session.summary.md # 可选：本 Session 结构化总结（总结 Agent 产出）
```

## Session 沙箱（你提到的「只能访问这个目录可读写」）

对齐现有 `WorkspaceSandbox` 语义：

- **读写**：`<agentRoot>/sessions/<sessionId>/workspace/**`（及未来若扩展，仍须路径 containment）。
- **只读挂载（逻辑层）**：`shared/**`、`docs/**`（通过专用工具或扩展 `read_file` 的多根只读根）。
- **禁止**：直接写 `shared/`、`docs/`（除非调用 `promote_*` / `publish_*` 类工具，内部校验 + 审计）。

> 说明：你消息里的「GitGS」在讨论稿中按 **「Agent 工具 / 工作区沙箱」** 理解；若本意是 **Git 工作区**，可在 [05-开放问题.md](./05-开放问题.md) 确认是否要为每个 Session 绑定独立 git 仓库或仅对 `shared/` 做 git 版本管理。

## 公共区 `shared/`

| 子目录 | 用途 | Session 内典型用法 |
|--------|------|-------------------|
| `shared/skills/` | 用户/Agent 进化出的 Skill | `SkillTool` / 生产力路径等价物加载；与仓库 `.claude/skills` 合并策略待定 |
| `shared/scripts/` | 可复用脚本（含 Weizhi/JS 等） | `execute_script`、bash 包装 |
| `shared/templates/` | 晋升时复制的起点 | 写 workspace 前复制模板 |
| `shared/mcp/` | MCP 清单与连接说明 | 自省与配置助手读取；密钥仍走 env/密钥存储 |

**命名与版本**：建议每个晋升条目带 `id`、`version`、`sourceSessionId`、`promotedAt`，避免同名覆盖 silent break。

## 文档区 `agentRoot/docs/`（与仓库 `doc/` 的关系）

- **仓库 `doc/`**：项目级设计、规范、路线图（**本规划系列**放这里）。
- **运行时 `agentRoot/docs/`**：**该用户 Agent 实例**的能力手册，随 `shared/` 增长而更新（索引、示例、deprecation）。

你提到「随着 Skill、脚本、MCP 增多，AI 不停去…」——讨论稿补全为：**AI 不停地刷新 `agentRoot/docs/capabilities/*` 与总索引**，必要时写 `journal/` 记录「新增了哪些公共能力、如何调用」。

## 权限矩阵（草案）

| 路径 | Session 工具读 | Session 工具写 | 总结/晋升 Agent 写 |
|------|----------------|----------------|---------------------|
| `sessions/<id>/workspace/` | ✓ | ✓ | ✓（同 Session） |
| `sessions/<id>/transcript.jsonl` | ✓（经 chat_history） | 仅运行时 append | 否 |
| `shared/` | ✓ | ✗ | ✓（晋升成功后） |
| `agentRoot/docs/` | ✓ | ✗ | ✓（文档维护 Agent） |
| `logs/events.jsonl` | 经 logs 子命令 | 运行时 append | 否 |

## 自省：`agent.manifest.json`

供系统提示与专用「meta 工具」读取，建议包含：

- `agentRoot` 各子目录说明；
- 当前加载的 skill/script/mcp 数量与扫描路径；
- 运行时限制（`AgentRuntimeDefaults` 摘要）；
- 指向 `docs/README.md` 与最近 Session 列表的指针（非全量 transcript）。

这样 Agent 在回答「你是谁、你能动什么、数据在哪」时有**单一事实来源**。
