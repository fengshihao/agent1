# 03 — 晋升与总结流水线

## 触发时机

| 触发 | 说明 |
|------|------|
| **Session 正常结束** | 用户 `/quit`、超时、或显式 `/summarize` |
| **Run 完成** | 可选轻量摘要写入 `runs/<runId>.json` 的 `summary` 字段 |
| **用户命令** | `/promote skill` / `/promote script` 从 `workspace/staging/` 提交审查 |

## 角色划分（逻辑 Agent，可先同一模型不同 system prompt）

1. **工作 Agent** — 当前生产力循环；只能在 Session `workspace/` 自由写。
2. **Session 总结 Agent** — 读 `transcript` + `events` + workspace 变更清单；产出 `session.summary.md`（结构化：目标、结果、未解决问题、**候选晋升列表**）。
3. **晋升 Agent** — 对候选项做：去敏、泛化、补全 SKILL  frontmatter、脚本参数化；输出到 `workspace/staging/` 再 **copy** 到 `shared/`。
4. **审查侧 API** — 与 Promotion API 同进程或独立调用；**初版始终 approve**，不做用户拦截（见 [06-环境文档与区外写入.md](./06-环境文档与区外写入.md)）。

工作 Agent **不能**直接写 `shared/` 或 `docs/`；总结 Agent 若运行在同一工具集下，同样只能写 Session 私有目录，晋升意图通过 **`promote_request`** 提交。

## 晋升流程（建议状态机）

```text
workspace 草稿
    → staging/（Session 私有目录内）
    → promote_request → Promotion API
    → 规则扫描（体积、路径、密钥 pattern、QuickJS 危险 API）
    → 审查 API（初版：自动同意）
    → shared/ 落盘 + docs/capabilities/ 更新 + manifest bump
    → events.jsonl: capability_promoted（事后审计）
```

后续加严：仅调整审查 API 策略或增加用户确认，**不**给工作 Agent 开放区外 write 工具。

## Skill 自创的具体形态

与 Claude Code 兼容：

```text
shared/skills/<skill-name>/
├── SKILL.md          # name、description、when to use、步骤
├── scripts/          # 可选
└── references/       # 可选
```

Session 内可先在同构的 `workspace/staging/skills/<name>/` 编辑，晋升时整目录移动/复制到 `shared/skills/`。

**加载顺序（待决）**：`shared/skills` 优先于仓库 `.claude/skills`，或合并去重以 `shared` 覆盖同名。

## 脚本晋升

- 要求附带 `scripts/<id>.meta.json`：`entry`、`runtime`、`inputs`、`sourceSessionId`。
- 与现有 `MutableScriptToolBridge` / Weizhi 环对接：晋升后注册到**全局**脚本桥（只读加载），而非仅当前 Session。

## 失败与回滚

- 晋升失败：保留 `staging/`，写 event `promotion_rejected` + 原因。
- 公共区回滚：依赖 `shared/` 下版本子目录或 git tag（若启用 git 层）。

## 与「访问对话历史」的关系

- **Session 内**：已有 transcript + `chat_history` 关键词检索。
- **跨 Session**：总结 Agent 可读 `list_sessions` + 按需读其他 Session 的 `session.summary.md`（**不默认读全量 transcript**，控制成本与隐私）。
- **长期记忆**：公共区 Skill/脚本 + `docs/` 索引 = 显式记忆；摘要链 = 压缩记忆。
