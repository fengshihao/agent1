# 07 — 系统提示词与环境摘要

> 2026-09-27：除只读 `docs/system/` 外，**每次 Run 的系统提示词里应内嵌环境要点**，避免 Agent 用多轮 `read_file` 才摸清目录、权限与职责。

## 为什么要两层

| 渠道 | 作用 | 粒度 |
|------|------|------|
| **系统提示词（内嵌摘要）** | 开局即知：我是谁、数据在哪、能写哪、不能做什么、怎么晋升 | 短、固定结构、带当前 Session 动态字段 |
| **`docs/system/**`（只读文件）** | 细则、示例、QuickJS 限制、故障排查 | 长、按需 `read_file` |

原则：**80% 的日常决策只靠提示词摘要即可**；只有改 Skill 规范、查完整路径表、或争议场景才读文档。

## 系统提示词应包含的块（建议）

与 [02-目录与权限模型.md](./02-目录与权限模型.md)、[06-环境文档与区外写入.md](./06-环境文档与区外写入.md) 对齐，拼装为固定小节（标题可中英混用，内容中文为主）：

### 1. 身份与职责

- 角色（生产力助手 / 工作 Agent / 子智能体变体）。
- 对用户负责什么：完成任务、在工作区内落盘、缺信息要问、不编造。
- 对**系统进化**负责什么（若启用）：在私有目录整理 staging、通过 **`promote_request`** 提交可复用 Skill/脚本，**不**私自写 `shared/`。

### 2. 目录结构（摘要树）

用 **10～20 行以内的 ASCII 或缩进列表**，写清 `agentRoot` 一级子目录及用途，并标 **R / RW / API**：

```text
agentRoot/
  sessions/<当前 sessionId>/workspace/  → 你的私有工作区（文件工具 RW）
  shared/                               → 公共能力（只读；写入仅 promote_request）
  docs/system/                          → 环境手册（只读）
  docs/capabilities/                    → 能力索引（只读）
  logs/events.jsonl                     → 审计事件（不可直接改）
```

**动态字段**（每 Session / 每 Run 注入）：

- `agentRoot` 绝对路径（或 `$AGENT1_AGENT_ROOT` 解析结果）
- 当前 `sessionId`
- 当前 `workspace` 绝对路径（现有 `buildEnvironmentSection` 已部分覆盖）
- 可选：`shared/catalog` 与 `shared/local` 条目数、**待同步更新数**（来自 `sync/state.json` 或最近一次 check，见 [08-云端资源同步.md](./08-云端资源同步.md)）

### 3. 权益范围（权限边界）

明确三条，减少试探性 tool call：

1. **可读可写**：仅 `sessions/<id>/workspace/**`（及工具文档中声明的相对路径规则）。
2. **可读不可写**：`shared/**`、`docs/**`；其他 Session 仅通过专用工具读摘要（若开放）。
3. **不可直接用文件工具写区外**；区外落盘 **只能** `promote_request` → Promotion API（初版自动同意，**事后 audit**）。

### 4. 工具与工作方式

- 文件：`read_file` / `write_file` / `edit_file` / `list_dir` 的**路径均相对 workspace**，除非后续增加「只读 agent 根」参数。
- 脚本：QuickJS / `execute_script` 仅在 workspace 内试跑。
- 历史：`chat_history` 等。
- 晋升：`promote_request` 的语义与 staging 约定（一句 + 指向 `docs/system/promotion.md`）。
- 云端资源：官方包在 `shared/catalog/`；**更新**用 `sync check` / `sync apply` 或 `catalog_sync_status`，**不要**尝试用 write_file 改 catalog；可信清单 URL 见 `docs/system/trusted-sources.md`。

### 5. 深入阅读指针（一行）

> 更完整的路径表、QuickJS 限制与示例见：`docs/system/directories.md`（需要时用 read_file，路径相对 agentRoot 或专用只读工具）。

避免在提示词里粘贴整篇 `directories.md`。

## 与代码的衔接（实现阶段，非本稿范围）

现状：`ProductivitySystemPromptBuilder` 仅注入工作区路径、日期、OS（见 `buildEnvironmentSection`）。

目标：

1. 新增 **`AgentEnvironmentSummary`**（或等价模块）：从 `agent.manifest.json` + 模板 **生成同一份摘要**，供：
   - `ProductivitySystemPromptBuilder.buildMainPrompt(...)` 注入；
   - 安装时写入 `docs/system/` 的「详细版」展开（**单一事实来源**，防提示词与文档漂移）。
2. 子智能体（explore / general / 未来的总结 Agent）使用 **裁剪版** 摘要：explore 强调只读；general 强调 workspace RW；审查侧 prompt **不含** workspace 写权限。
3. **Token 预算**：摘要块建议 **800～1500 汉字** 上限；超长清单（全部 skill 名）放 `docs/capabilities/`，提示词只写「共 N 个，见索引」。

## 反模式

- 只依赖文档、提示词不写边界 → 浪费轮次、易越权尝试写 `shared/`。
- 提示词全文复制 `docs/system/` → 上下文膨胀、版本升级难 diff。
- 提示词与 `docs/system/` 手工各写一套 → 必然不一致；应模板化生成。

## 验收标准（讨论用）

- 新 Session **第一轮**用户说「把 reusable 脚本晋升到公共区」时，模型应能说出：先放 workspace/staging、再 `promote_request`，**无需先读 3 个 md 文件**。
- 新 Session 用户说「改一下系统目录说明」时，模型应拒绝直接 write，并说明只有产品安装包或 Promotion 流程可改区外文档。
