# 01 — 愿景与原则

## 我们要做什么

构建一个**可以自我进化**的 Agent 系统，核心能力包括：

1. **自创 Skill** — 在运行中沉淀、封装可重复的工作流（不仅是加载仓库里固定的 `.claude/skills`）。
2. **访问对话历史** — 跨 Run、跨 Session 检索「之前说过什么、做过什么」（已有 `transcript.jsonl`、`chat_history` 等方向，需扩展到「自省」层级）。
3. **操纵自身组件** — 理解并安全地配置/调用自己的工具链、脚本引擎、MCP、日志与数据目录（**强自省**，而不是黑盒调用）。
4. **通用结果持久化** — 单次 Session 的产出中，可复用部分进入**公共层**，供后续 Session 只读复用；不可复用部分留在 Session 私有工作区。

## 设计原则（讨论共识草案）

| 原则 | 说明 |
|------|------|
| **Session 隔离** | 每次对话（Session）有独立工作目录；默认可写范围仅在该 Session 沙箱内。 |
| **公共只读 + API 写入** | `shared/` 等区外对工作 Agent **只读**；区外落盘只走 **Promotion API**，禁止用 `read_file`/`write_file` 绕过。 |
| **晋升而非复制粘贴** | 总结 Agent 在私有目录产出 staging，经 **promote_request → 审查 API** 落入公共区；**初版审查自动同意**。 |
| **环境文档只读** | `docs/system/` 由我们写好，供 Agent **Read 理解环境**；不可由工作循环直接修改（见 [06-环境文档与区外写入.md](./06-环境文档与区外写入.md)）。 |
| **提示词内嵌摘要** | 系统提示词注入目录/权限/职责**要点**，减少开局多轮读文档（见 [07-系统提示词与环境摘要.md](./07-系统提示词与环境摘要.md)）。 |
| **事后审计** | 不做用户事前确认；所有晋升请求与结果写入 `events.jsonl`（及可选专用 audit 日志）。 |
| **与仓库代码分离** | 运行时数据在 `AGENT1_AGENT_ROOT`；仓库 `.claude/skills` 为出厂预置；**云端 catalog** 与 **local 晋升** 分目录（见 [08-云端资源同步.md](./08-云端资源同步.md)）。 |
| **Rsync 式资源同步** | 远程清单 + 本机 state 对比（rsync-like），只拉变更；AI 通过摘要/工具知悉 pending，不全量重下。 |

## 非目标（当前阶段）

- 不在第一版追求「无监督全自动改自己的 JAR/二进制」。
- 不默认把公共区变成任意 Session 可写的共享盘（避免污染与 prompt 注入面扩大）。
- 不把 Git 操作等同于 Session 沙箱（Git 可作为**可选**版本化层，见目录文档）。
