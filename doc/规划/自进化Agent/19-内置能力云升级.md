# 19 — 内置能力云升级

> 2026-10-09。承接 [08-云端资源同步](./08-云端资源同步.md) 已落地的清单 diff，解决另一件事：**打进 App / jar 的脚本、模板、能力卡、Skill 要能不发版就换新**。
> 存储只是一个 HTTPS 源。默认指向维护者自己的对象存储（当前准备用阿里云 OSS 公共读前缀或前面的 CDN）。换桶、换云、自建静态站，只改一个 manifest URL。
> **本期不做**「只有官方 App 能连上桶」。文末只记录以后怎么加，避免现在把厂商 SDK 和密钥焊进客户端。

关联：`CatalogSyncService`、`CatalogSyncConfig`、`AgentHomeBootstrap`、`OfficeCatalogScripts`、`WebLibCatalogTemplates`、`AndroidOfficeCatalogSync`、`CapabilityIndexStore`、`AgentSkillLoader`。

---

## 1. 现状：协议有了，预置内容没走它

桌面 CLI 已经能 `sync check` / `sync apply`：GET `catalog-index.json`，按 `id + digest` 只拉变更，校验 sha256 后落盘。客户端不认识 COS / OSS，只要对象能被 HTTPS GET。仓库里没有阿里云 OSS SDK，也没有把 AccessKey 放进 Agent 的测试；之前能测的是**公共读 URL**（见 `dev/catalog-sample/CLOUD-E2E.md`）。

真正挡住「改脚本不用发版」的是下面几条：

| 事实 | 后果 |
|------|------|
| `agent.manifest.json` 里 `catalog.manifestUrl` 默认为空；没有官方默认地址 | 用户和 Android 都不会自己去拉 |
| Android 宿主不调用 `CatalogSyncService` | 手机上的能力永远停在 APK 里那一份 |
| `WebLibCatalogTemplates.ensure` 每次启动都 `REPLACE_EXISTING` | 云端更新的 HTML 薄壳下次启动被 jar 盖回旧版 |
| `AndroidOfficeCatalogSync` 每次从 `assets/office/` 覆盖 `shared/catalog/scripts/` | 同上，而且比桌面更彻底（桌面 `OfficeCatalogScripts` 是「文件非空就跳过」，旧文件又永远不会被更新的 APK 换掉） |
| `CapabilityIndexStore` 按 classpath 种子指纹重建 SQLite | 只更新 `docx.js` 而不同步 `office-api-cards.jsonl`，`find_caps` 仍指向旧入口 |
| `AgentSkillLoader` 的 `skill-creator` / `pptx` 从 classpath 读 | 磁盘上的 catalog 可以覆盖同名，但没有默认源去覆盖 |

所以下一步不是再设计一套同步协议，而是：**给已有 sync 一个默认源，让 Android 在启动时对「内置包」自动 apply，并改掉种子覆盖规则。**

---

## 2. 目标与非目标

| 要 | 不要 |
|----|------|
| 不发 APK / jar，就能更新 Office 脚本、HTML 薄壳、能力卡、随包 Skill | 用云升级替换 App 商店的安装包更新 |
| 默认连维护者的桶；嵌入方或用户改一个 URL 就能换源 | `agent_core` 依赖阿里云 SDK、OSS 签名、RAM 角色 |
| 无网时用包内种子，能离线开聊 | 启动被网络挡住 |
| 脚本和它的 `find_caps` 卡片一起升 | 只换文件、索引仍是旧的 |
| 用户 `shared/local/` 晋升结果仍优先于云端 | 云端覆盖用户自己晋升的同名技能 |

明确不进第一期云通道：Weizhi 原生 `.so`、WebView 引擎、和界面版本绑死的 UI 生成提示词、审查模式 `inspect.js`（它和预览页 Kotlin 是同一份契约，跟包走）。

## 3. 源模型：一个 URL，三层内容

```text
包内种子（离线地板）
        │  仅当磁盘没有更新的已装版本时写入
        ▼
官方云 catalog（默认 manifest URL）
        │  sync apply，digest 校验
        ▼
shared/catalog/  +  能力索引里 source=official 的行
        │
        ▼
shared/local/    用户晋升，加载时覆盖同名
```

**客户端只认 HTTPS。** 默认地址放在 core 里**一个**常量（例如 `OfficialCatalog.DEFAULT_MANIFEST_URL`），解析顺序保持现有规则，并在最前面加默认值：

1. 环境变量 `AGENT1_CATALOG_MANIFEST_URL`（测试、CI、换源）
2. `agent.manifest.json` → `catalog.manifestUrl`（用户或嵌入方写死自己的源；空字符串表示「用默认」）
3. 编译进 core 的官方 URL

官方 URL 指向维护者的 OSS 前缀或 CDN，例如：

```text
https://<bucket>.<region>.aliyuncs.com/agent1/catalog/v1/catalog-index.json
```

`catalog-index.json` 里的 `baseUrl` 与该前缀一致。换腾讯云 COS、R2、GitHub Release、自建 Nginx，客户端代码不动。

发布侧用 `ossutil`（或控制台）上传，不进 Agent 进程。仓库可以有一个 `scripts/publish-catalog.sh`：对 `agent-home/` 里要发布的文件算 sha256、写出 `catalog-index.json`、在本机配置了 ossutil 时上传。密钥留在发布机器，不进 git。

## 4. 第一期上云的条目

沿用现有 manifest 字段：`id`、`kind`、`version`、`digest`、`path`、`sizeBytes`。同一 id 在包内种子清单和云端清单里必须一致，diff 才有意义。

| id 示例 | kind | 现在的真源 | 落盘 |
|---------|------|------------|------|
| `script.docx` 等五个 Office 文件，或一个 `bundle.office-scripts` | `script` / `bundle` | `agent-home/catalog/scripts/docx*.js`、`pptx*.js`；Android 还有 `assets/office/` | `shared/catalog/scripts/` |
| `script.svg-raster` | `script` | `svg-raster.js` | 同上 |
| `template.three`、`template.mermaid` … | 新增 kind `template`（或先用 `data`，目录规则单独映射到 `templates/`） | `agent-home/catalog/templates/*.html` | `shared/catalog/templates/` |
| `capability.office-cards`、`capability.web-lib-cards`、`capability.weizhi-cards`、`capability.search-seed` | 新增 kind `capability` | `agent-home/capabilities/*.jsonl` | 不给模型当脚本读；apply 后并入 SQLite |
| `skill.pptx`、`skill.skill-creator` | `skill` | `agent-home/skills/*/SKILL.md` | `shared/catalog/skills/<id>/` |

`update` 字段（可选，缺省 `manual`）：

| 值 | 行为 |
|----|------|
| `auto` | 宿主启动后后台 apply。第一期内置包全部标 `auto` |
| `manual` | 维持今天的 `catalog_install` / 用户显式 sync。可选的大库、native 以后用这个 |

包内同时带一份 `bundled-catalog-index.json`（id、version、digest，无远程 `baseUrl` 依赖）。它是「这台安装包认为的地板」，不是第二套下载协议。

## 5. 种子不再无条件覆盖

今天三种策略互相打架。统一成一条规则，桌面和 Android 共用（Android 的 `assets/office` 只是种子字节的另一份拷贝，不是更高优先级）：

对每个内置 id，比较三份 digest：

1. **已装记录**（`sync/state.json` 里该 id 的 digest，且磁盘文件校验仍匹配）
2. **包内种子** digest
3. **云端清单** digest（有网且 check 成功时）

写入规则：

- 已装 digest 与云端一致 → 不动文件。启动时的种子拷贝**禁止**覆盖它。
- 包内种子 digest 与已装不同，且种子 `version` 更高（App 升级带了更新的脚本）→ 用种子覆盖，并改 state。这样「发了一版 APK」仍能抬高地板。
- 云端 digest 与已装不同，且云端 version 不低于包内种子 → `auto` 条目后台 apply。
- 无网、check 失败 → 保留磁盘；磁盘没有该文件时才从种子补。
- digest 校验失败 → 不落盘，沿用上一份好文件，记 `catalog_sync_*` 错误。

`version` 用单调整数或 `yyyy.mm.dd.n`，字符串比较不够时在发布脚本里保证可比较。第一期可以规定：**version 为十进制整数，数值大者为新**。

能力卡：apply `kind=capability` 后，按 `source=official` 替换对应 jsonl 导入的行，不重建整库，以免抹掉 MCP 同步进来的条目（与现有 `McpCapabilitySync` 按 kind 替换同一思路）。`find_caps` 在同一次启动的 apply 完成前仍可读旧索引，apply 后下次检索即新卡。不要求聊天进行中热切换。

Skill 加载顺序不变：bundled classpath → project → **catalog（含云端落下的）** → local。local 仍赢。

## 6. Android 何时拉

生产力宿主起来、`AgentHomeBootstrap.ensure` 完成之后：

1. 先按第 5 节用种子把缺失文件补齐（聊天可立即用）。
2. 后台线程 `sync check`；对 `update=auto` 且 pending 的 id 调用已有 `apply`。
3. 失败只记日志 / 事件，不弹阻塞对话框，不重试风暴（当次进程最多一次；下次冷启动再试）。
4. apply 成功后刷新能力索引的 official 行。Office 脚本目录已是 Weizhi `scriptFolder`，文件替换后**下一次** `run_js` 读到新文件即可，不必重启进程。

桌面 CLI 同样：`ProductivityAgentHost` 启动时对 `auto` 条目做一次 check/apply（可用环境变量关掉，避免单测打网）。单测继续用 MockWebServer，不访问真实 OSS。

## 7. 发布一个版本时人要做什么

1. 改 `agent_core/src/main/resources/agent-home/` 里的脚本或卡片（仓库仍是真源；APK `assets/office` 继续做离线副本，直到种子拷贝收口到一处）。
2. 跑发布脚本：重算 digest、递增 version、写出 `catalog-index.json`。
3. `ossutil cp` 到官方前缀（先传对象，最后原子地覆盖 `catalog-index.json`，避免清单指向尚未传完的文件）。
4. 已安装的 App 下次启动拉到 diff。没装新 APK 的用户也能拿到脚本更新。
5. 发 APK 时种子 digest 与当时云端一致，新安装无网也是新地板。

桶策略第一期：**该前缀公共读**。内容不是密钥；完整性靠 digest，不靠「别人下不到」。

## 8. 分期

| 期 | 做什么 | 验收 |
|----|--------|------|
| **C0** | 本文。不改运行时 | 评审通过再写代码 |
| **C1** | 包内 `bundled-catalog-index.json` + 第 5 节覆盖规则。桌面/Android 种子都走它。无网络 | JVM 单测：云端 digest 已装时，bootstrap 不再覆盖；种子 version 更高时覆盖；Android office 不再每次 REPLACE |
| **C2** | 官方 URL 常量 + 启动时对 `auto` apply。Android 调用 core 的 `CatalogSyncService`。能力卡 apply 后更新索引 | MockWebServer：改远程 digest → apply → 磁盘与索引变；无 URL / HTTP 失败时仍可用种子 |
| **C3** | 发布脚本 + 维护者桶上的真实前缀；把常量写成该 URL | 手测：不装新 APK，只上传新 `docx.js`，下次启动 `find_caps` 与脚本内容变 |

C1 不依赖阿里云。C3 才需要桶。C2 的默认 URL 在 C3 之前可以是空：空则跳过云端，只验证注入 URL 的路径。

## 9. 以后：怎样做到「只有自己的 App 能读桶」

第一期公共读谁都能 GET。若以后要限制调用方，限制的是**桶的读取账单和清单枚举**，不是「文件到了手机上别人就复制不走」。脚本必须在设备上执行，`adb` 或改过的包总能读 `shared/catalog/`。做不到把内容只留在「正版进程的内存里还不被导出」。

可行的加装方式（不改 sync 的 diff 语义）：

1. 桶改为私有，删掉公共读。
2. 在 OSS 前面放一个很小的发证接口（云函数即可，不必进 `agent_core`）：确认调用方是官方签名的 Android 包（Play Integrity 或等价的应用完整性证明，核对签名证书），再签发**只读、只覆盖 catalog 前缀、十几分钟过期**的 STS。
3. `CatalogSyncService` 增加可选的请求修饰钩子（例如每个 GET 前附上 `Authorization`）。默认空实现，公共读行为不变。阿里云 STS 的具体换票放在钩子实现或独立小模块，核心仍然只发 HTTPS GET。
4. AccessKey 永远不进 APK。Referer、User-Agent 白名单可以伪造，不能当这个限制。

嵌入方若使用自己的私有桶，同一钩子由他们自己的发证服务填充。官方 STS 不是唯一允许的鉴权。
